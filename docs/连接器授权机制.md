# 连接器授权机制：为什么官方连接器有授权弹窗，自定义 MCP 没有

> 简短回答：**授权弹窗是「连接器包」里的 `token-schema.json` 驱动的，属于连接器元信息；  
> 而 `~/.workbuddy/mcp.json` 是裸 MCP 配置，不携带任何授权元信息，因此永远不会弹窗。**

你的观察完全正确，这确实是两条不同的路径，而不是配置写错。

---

## 一、两条路径的本质区别

| 维度            | 官方连接器（市集）                                                  | 自定义 MCP（`~/.workbuddy/mcp.json`） |
| ------------- | ---------------------------------------------------------- | -------------------------------- |
| 定义文件          | `mcp.json` + **`token-schema.json`** + `icon.svg` + skills | 仅 `mcp.json`                     |
| 来源            | 云端市集 zip 解压                                                | 本地手写                             |
| `${VAR}` 解析来源 | **用户填写后加密存储的值**                                            | **系统环境变量**                       |
| 授权界面          | ✅ 弹窗表单 / 浏览器 OAuth                                         | ❌ 无                              |
| 凭证存放          | 加密在 `connector-states.v3.json`                             | 明文写在配置里（或走环境变量）                  |
| 启用方式          | 连接器中心 → 连接/授权                                              | 自定义连接器 → 信任                      |

## 二、本机实测：连接器包的真实结构

### 市集连接器存放位置

```
~/.workbuddy/connectors-marketplace/connectors/<connector-name>/
├── mcp.json            # MCP 服务定义（用 ${VAR} 占位）
├── token-schema.json   # 授权表单定义 —— 弹窗就来自这里
├── cli.json            # CLI 类型连接器（代替 mcp.json）
└── skills/             # AI 使用说明
```

本机统计（268 个官方连接器）：

```
227 个有 mcp.json
 59 个有 token-schema.json   ← 这些会弹「填写凭证」表单
 46 个有 cli.json            ← CLI 类型
  0 个有 connector-meta.json ← 本地不存在，属提交审核时的元信息
```

市集来源：

```json
{
  "sourceKey": "workbuddy-connector-official\nhttps://static.workbuddy.cn/connectors-config-v2/connectors-config.zip"
}
```

### 实例 1：带授权弹窗的连接器（腾讯地图）

`tencent-map/mcp.json`：

```json
{
  "mcpServers": {
    "tencent-map": {
      "type": "sse",
      "url": "https://mcp.map.qq.com/sse?key=${TENCENT_MAP_KEY}&format=0",
      "timeout": 30000
    }
  }
}
```

`tencent-map/token-schema.json`：

```json
{
  "title": "腾讯地图 Key 配置",
  "description": "连接你的腾讯地图开发者 Key……Key 仅存储在本机 ~/.workbuddy下。",
  "docUrl": "https://lbs.qq.com/dev/console/quick-register",
  "docLabel": "如何获取腾讯地图 Key？",
  "fields": [
    { "key": "TENCENT_MAP_KEY", "label": "Key", "type": "text", "required": true }
  ]
}
```

**注意两者如何配合**：`mcp.json` 里写 `${TENCENT_MAP_KEY}`，`token-schema.json` 定义  
`TENCENT_MAP_KEY` 这个字段 → WorkBuddy 弹出表单 → 用户填写 → 值被注入占位符。

### 实例 2：免认证连接器（无 token-schema）

```
24haowan/mcp.json
{
  "mcpServers": {
    "24haowan": { "type": "streamableHttp", "url": "https://mcp.24haowan.com/mcp" }
  }
}
```

没有 `token-schema.json`、没有 `${VAR}` → **点连接直接通，不弹任何东西**。

这恰好就是你的 `workbuddy-connector` 现在的状态。

## 三、自定义 MCP 的 `${VAR}` 走的是环境变量，不是弹窗

官方 CLI 文档（`workbuddy.cn/docs/cli/mcp`）明确规定：

> **环境变量扩展**：MCP 配置支持环境变量扩展，允许在配置中引用系统环境变量。
>
> - `${VAR_NAME}` — 展开为环境变量 VAR_NAME 的值
> - `${VAR_NAME:-default_value}` — 未设置时使用默认值
> - **变量名必须以大写字母或下划线 `[A-Z_]` 开头**，后续只能是 `[A-Z0-9_]*`
> - 小写、混合大小写、数字开头的变量**不会被展开**
> - 支持字段：`url`、`headers`（以及 stdio 的 `command`/`args`/`env`）
> - 未设置且无默认值时：**保留原始占位符 `${VAR}` 并报告 WARNING**，配置不会失败

**关键结论**：自定义 `mcp.json` 里写 `${MY_TOKEN}`，WorkBuddy 会去**系统环境变量**找  
`MY_TOKEN`，**不会弹窗让你填**。

> 实践提示：变量名必须大写。写 `${myToken}` 或 `${my_token}` 不会被展开，会原样保留并告警。

## 四、用户凭证存在哪里（实测）

```
~/.workbuddy/connectors/<userId>/
├── .credentials.v3.json      # 加密后的 OAuth 令牌
├── .master.key               # 本地加密密钥（误删 → 所有连接器需重新授权）
├── connector-states.v3.json  # 加密后的连接器状态（含注入用 token / API Key）
└── README-DO-NOT-DELETE.txt
```

`connector-states.v3.json` 的关键字段：

```json
{
  "enabled": [],
  "everConnected": [],
  "headerOverrides": {},     // ← 注入到 headers 的用户凭证
  "envOverrides": {},        // ← 注入到 env 的用户凭证
  "encryption": { "scheme": "aes-256-gcm", "kdf": "hkdf-sha256" }
}
```

README 原文：

> `connector-states.v3.json` 加密后的连接器状态（**含注入用 token / API Key**）  
> `.master.key` 本地加密密钥（**误删将导致所有连接器需要重新授权**）

也就是说：**用户在弹窗里填的值，加密后存在这里，连接时注入 `${VAR}` 占位符。**  
自定义 `mcp.json` 没有这个环节，所以也读不到这里的凭证。

## 五、想获得授权弹窗体验，怎么做

### 路径 A：打包成正式连接器包（唯一正规方式）

目录结构（参考百度地图官方仓库 `baidu-maps/workbuddy-agent-plugin`）：

```
your-connector/
├── connector-meta.json    # 元信息（name / source / type / version / auth_mode）
├── mcp.json               # MCP 服务定义，用 ${VAR} 占位
├── token-schema.json      # 授权表单（auth_mode: "token" 时必需）
├── icon.svg               # 市集图标
└── skills/{name}/SKILL.md # AI 使用说明（可选但推荐）
```

`connector-meta.json` 中声明认证方式：

```json
{
  "name": "日程服务",
  "source": "your-schedule-connector",
  "type": "mcp",
  "version": "1.0.0",
  "auth_mode": "token",
  "minWorkbuddyVersion": "4.23.0",
  "examples_zh": ["查一下我今天的日程", "下周有哪些会"]
}
```

`auth_mode` 取值：

| 取值                        | 效果                                   | 用户看到什么                          |
| ------------------------- | ------------------------------------ | ------------------------------- |
| 省略                        | 标准 MCP OAuth（服务端需实现 OAuth 2.1 资源服务器） | 需授权时打开浏览器                       |
| `token`                   | 用户自填凭证                               | **弹出表单**（需 `token-schema.json`） |
| `server-side` / `gateway` | WorkBuddy 云端托管 OAuth                 | 打开浏览器授权                         |

完成后打包提交 WorkBuddy 团队审核，进入连接器市集。

**审核要点**（官方要求）：

- `mcp.json` 中**不得写入真实凭证**，只能用 `${VAR}`
- `${VAR}` 占位符名必须与 `token-schema.json` 的 `fields[].key` **完全一致（区分大小写）**
- 敏感字段一律用 `type: "password"`
- 远程 MCP 必须 HTTPS
- 一个连接器只配置一个 MCP Server

### 路径 B：不审核，用环境变量（立即可用，但无弹窗）

在自定义 `mcp.json` 里用系统环境变量：

```json
{
  "mcpServers": {
    "workbuddy-connector": {
      "type": "sse",
      "url": "http://localhost:3100/sse",
      "headers": { "Authorization": "Bearer ${SCHEDULE_TOKEN}" }
    }
  }
}
```

然后每个用户在自己的系统里设置环境变量：

```bash
export SCHEDULE_TOKEN="<各自的 token>"
```

**代价**：没有弹窗、没有加密存储、需要用户手动配环境变量，且要重启 WorkBuddy 才生效。

### 路径 C：直接写明文（最省事，仅限本机调试）

就是当前配置的做法。适合单人调试，不适合多人分发。

## 六、一句话总结

| 你的疑问              | 答案                                         |
| ----------------- | ------------------------------------------ |
| 为什么官方连接器有授权弹窗？    | 它的包里带 `token-schema.json`，WorkBuddy 据此生成表单 |
| 为什么我的没有？          | `~/.workbuddy/mcp.json` 只是裸 MCP 配置，没有授权元信息 |
| 我的 `${VAR}` 会弹窗吗？ | 不会。它去**系统环境变量**取值，不是弹窗                     |
| 想要弹窗怎么办？          | 打包成连接器包（含 `token-schema.json`）提交审核上架       |
| 不想审核怎么办？          | 路径 B（环境变量）或路径 C（明文），但没有弹窗和加密存储             |



> 补充：`x-workbuddy` 是 WorkBuddy 私有字段；连接后写入用户「自定义连接器」的配置中  
> 会被**剥离**，不会污染用户本地 `mcp.json`。因此连接器包里的私有元信息不会被带到用户机器上。
